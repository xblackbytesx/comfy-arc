# Agent notes

The canonical architecture contract for this repo.

A ComfyUI container image for Intel Arc (XPU) whose single promise is that a
build of a given commit always produces the same running software. Everything
below exists to keep that true.

## Invariants

1. **Nothing installs at runtime.** No package manager, no node manager, no
   `pip install` in the entrypoint. ComfyUI-Manager is deliberately not in the
   image, and must not be added: it installs packages on startup, which is how
   these setups drift into "booted yesterday, not today".
2. **Every version is pinned in the repo.** The Fedora base by digest,
   `COMFYUI_VERSION`, `TORCH_VERSION`, `TORCHVISION_VERSION` and
   `TORCHAUDIO_VERSION` in `Dockerfile`, one commit per node in `nodes.list`,
   and every Python package with hashes in `requirements.lock`. A branch name
   is never acceptable; CI fails on anything that is not a full 40 character
   sha. Fedora rpms are the one exception (the update repos keep only the
   newest build); the image records them in `/opt/comfy-arc-rpms.txt`.
3. **The lock is the whole Python environment.** `requirements.lock` is
   generated by `scripts/lock.sh`, never edited, and installed in one step with
   `--require-hashes --no-deps --only-binary=:all:`, so the build resolves
   nothing. Its `# inputs:` stamp hashes the pins it was made from; CI runs
   `scripts/lock.sh --check`. The installed set becomes
   `/etc/comfy-arc-constraints.txt` for ComfyUI's and each node's
   `requirements.txt`, and the build fails if those installs change anything.
4. **The image holds the application, the mount holds data.** Only
   `$COMFY_DATA_DIR` (default `/data`) is written to, plus the temp dir.
   Deleting the mount must never stop ComfyUI from starting. Custom nodes stay
   inside the image, which is why `--base-directory` is not used: it would
   relocate `custom_nodes` onto the mount.
5. **Configuration is environment variables, resolved in `entrypoint.sh`.**
   Bad values exit non-zero with a message naming the variable. Never quietly
   fall back to a default.
6. **The assembled command is printed** before exec, so a container states what
   it is running.
7. **The idle unloader never frees while the queue is busy.** `idle-unload.sh`
   checks `/queue` and only calls `/free` after `COMFY_IDLE_UNLOAD` seconds
   with nothing running or pending, once per idle period. A transient failure
   to reach the server is a skipped round, never an unload.
8. **Privileges drop when asked, never silently.** With `PUID`/`PGID` set and
   the container started as root, `entrypoint.sh` creates that account, adds
   the group owning `/dev/dri/render*` so the GPU stays visible, chowns the
   directories it creates (never recursively: a models tree can be terabytes)
   and execs through `setpriv`. Started with docker's `user:`, it says so and
   changes nothing. Caches (SYCL, Hugging Face, torch, HOME) live under
   `$COMFY_DATA_DIR/cache` so they survive container replacement.

## Layout

| Path | Role |
|---|---|
| `Dockerfile` | the image: Intel runtime, PyTorch XPU, ComfyUI, nodes, manifest |
| `nodes.list` | `<name> <git url> <commit>`, one node per line |
| `requirements.lock` | every Python package, exact version + sha256 (generated) |
| `scripts/lock.sh` | regenerates the lock with uv; `--check` compares it to the pins |
| `patches/xpu_int8.py` | build-time edits so int8/w4a8 run on int8 kernels on XPU |
| `entrypoint.sh` | environment variables to ComfyUI flags, then exec |
| `docker-compose.yml` | reference deployment, pulls GHCR or builds locally |
| `workflows/` | ready-made workflows (core nodes only) and the models they need |
| `.github/workflows/ci.yml` | hadolint, shellcheck, compose config, pin and lock checks |
| `.github/workflows/release.yml` | tag or manual run to GHCR |

## Making changes

- **Upgrade ComfyUI or PyTorch:** change the ARG, run `scripts/lock.sh`,
  rebuild, tag a release. torchvision and torchaudio must match the torch
  build (check `Requires-Dist` in their XPU wheels).
- **Refresh the other Python packages** without changing a pin: run
  `scripts/lock.sh`; it re-resolves to the newest compatible versions.
- **Add or update a node:** one line in `nodes.list`, run `scripts/lock.sh`,
  rebuild.
- **Fedora:** stays on the newest release whose default Python has wheels for
  the whole lock (`--only-binary` in `scripts/lock.sh` proves it). Moving
  means changing `FROM` (tag + digest), `PYTHON_VERSION` in `scripts/lock.sh`,
  the `python3.X-devel` package and the rpmfusion URL together.
- **New tunable:** add it to `entrypoint.sh` with a default and validation, to
  the table in `README.md`, and to `.env.example`. Compose passes it through.
- **Never** add a step that fetches anything at container start.
- **`patches/xpu_int8.py` fails the build** when an upgrade moves its anchors.
  Check whether upstream now handles XPU itself and drop that edit, rather than
  loosening the match.

## Testing without Docker

The build is its own first test: it imports torch after registering the
loader paths, so a missing Intel runtime library (libsycl and friends, which
the XPU wheels drop into `/usr/local/lib`) fails the build rather than every
container start. Keep that check.

`entrypoint.sh` is testable on its own: put a stub `python3` on `PATH` that
echoes its arguments, set `COMFY_DATA_DIR` to a temp dir, and check the flags
for each configuration plus the failure cases. `shellcheck entrypoint.sh` and
`python3 -c "import yaml; yaml.safe_load(open('docker-compose.yml'))"` cover
the rest. The image build itself needs a real Docker daemon.

## Release

Tag `vX.Y.Z` and push. The workflow builds `linux/amd64` only (Arc is x86) and
publishes `vX.Y.Z`, `X.Y`, `X` and `latest` to
`ghcr.io/<owner>/comfy-arc`. Manual runs publish a short-sha tag and leave
`latest` alone.
